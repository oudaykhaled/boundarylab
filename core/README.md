# BoundaryLab Kotlin core

Reuse the bounded engine and FieldPack codec in a JVM 17 application without
Android classes or Binder. Publish from the repository root:

```sh
./gradlew publishLibrariesToLocalRepository -PboundarylabRepository=/absolute/path/to/maven
```

Configure that folder as a Maven repository restricted to `dev.boundarylab`, then
add `implementation("dev.boundarylab:boundarylab-core:0.1.0-SNAPSHOT")`. This is a
local development artifact, not a Maven Central availability claim. POM/module
metadata, sources and Dokka HTML API docs accompany the JAR. The default producer
folder is `build/local-maven`; producer and consumer versions must match.

The [library guide](../docs/LIBRARY-GUIDE.md) covers repository setup, and the
[standalone JVM consumer](../examples/standalone/README.md) executes generated
SHA-256 and a FieldPack round trip using only the published coordinate. Embedding
the core runs work in your own process; use a transport host when you need a
separate worker process.

`dev.boundarylab.core` implements the volatile job policy in
[ADR-B02](../docs/decisions/BUILD-DECISIONS.md) and the
[FieldPack contract](../docs/FIELDPACK.md). It has no Android, transport, coroutine,
or JSON runtime dependency. `FieldPackCodec` validates a whole bounded manifest
before any adapter opens an attachment.

`CoreEngine()` starts one daemon worker and advertises generated hashing.
An adapter enables `enableFileOperation = true` only after proving its input
validation requirements. The transport supplies authenticated owner identity;
callers never gain authority by choosing an owner string on the wire.
Every job operation requires owner, session and process epoch. Use
`statusByRequest` to resolve ambiguous admission in the same surviving session;
the core does not replay jobs after process loss.

`submit` consumes a supplied `PositionalSource` on every outcome. Adapters close
handles when validation fails before submission; the core closes transferred
handles on rejection, duplicate, cancellation, session cleanup and worker exit.
The source exposes captured size, positional reads and mandatory final mutation
validation. Positive partial reads accumulate; zero progress, premature EOF,
oversize return values, read errors, observed growth and metadata changes cannot
produce success. Generated bytes follow `(seed + position) & 255`.

State changes share one monitor; content reads and source closes execute outside
it. Round robin chooses sessions at job boundaries. Running cancellation records
intent and leaves the worker occupied through read and close completion. A
blocked operating-system read has no invented interruption deadline. `close()`
revokes sessions and requests cancellation; it does not join or kill a blocked
worker. Queued source cleanup can make the caller's close/cancel call wait for
the adapter's close, while other state operations remain available.

The exact baseline limits live in `EngineLimits`. Lower limits are allowed for
constrained hosts and cap tests; raising contract limits is rejected. Retained
bytes account for the canonical request encoding plus a conservative 768-byte
snapshot envelope, excluding JVM object/runtime overhead. Results expire lazily
on state operations, after 60 seconds, or oldest-first when count/byte limits
require eviction. Metrics distinguish queued, physical running, retained and
owned-source counts. These counters are not an operating-system FD or RSS
measurement.

`autoStart = false`, a supplied `MonotonicClock`, and synchronous `runNext()`
support deterministic tests using the same admission/scheduling/worker code.
The test suite uses independent Python SHA-256 vectors from
`conformance/shared/digest-v1.json`, fake positional sources, and latches for
blocked-read interleavings. Run `./gradlew :core:test` from the repository root.
These tests prove core behavior; they do not establish Android FD safety,
Binder identity capture, desktop rooted-file containment, or process-boundary
execution.
