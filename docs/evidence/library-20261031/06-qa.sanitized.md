## 3. Source-level risks and limitations

No unconfirmed defect is promoted to a finding. Some broker lifecycle tests use controlled Binder/PackageManager contexts; their source labels these explicitly. They prove SDK control flow and predicate rejection, while the outside consumer and separate-signer fixtures supply real installed process/package boundary proof. Isolated permission owner/protection negatives mutate installed metadata in test doubles; they are not malicious APK installation scenarios.

Sample export is asynchronous and a provider write already started may finish after Activity stop; stale UI completion is discarded. That race was source-reviewed, not runtime stress-tested here. File support is whole, regular, bounded, read-only documents; no PDF extraction, arbitrary cloud/pipe provider support or malicious-content classification is established.

## 4. CTA / entry-point inventory

- Standalone consumer: `choose_document` opens ACTION_OPEN_DOCUMENT; result opens a read-only FD and submits through configured SDK; `export_manifest` opens ACTION_CREATE_DOCUMENT; `run_workload` executes generated SHA-256. All three visible CTAs were exercised through real Android taps. Source: `examples/standalone/android/src/main/kotlin/dev/boundarylab/consumer/MainActivity.kt:59`.
- SDK: preserved default constructor and additive explicit `BrokerEndpoint(component, permission)`; reciprocal identity checks before binding/handshake. Source: `sdk/kotlin/src/main/kotlin/dev/boundarylab/sdk/BoundaryClient.kt:158`.
- Services: default `dev.boundarylab.broker` and custom `dev.boundarylab.qa.broker`, stable class `dev.boundarylab.broker.BoundaryBrokerService`, respective signature permissions. These are explicit bound-service addresses, not deep-link destinations.
- Test principals: native consumer owner fixture, independently signed denied caller, same-address re-signed broker. No root, shared UID, signer bypass or alternate unintended tap path was used.

## 5. Coverage gaps / smallest next gate

Only current-source API 35 virtual execution is claimed. Historical API 36 physical and AOSP image receipts remain separate. Flutter runtime and platform bridge/native OS image were not exercised. Rotation/process recreation, picker cancellation, provider loss/unsupported-provider UI, export-stop races, broad accessibility and performance/soak are untested in this campaign. A future SAF UI regression flow should cover choose/cancel/export and Activity recreation; retain existing FD/ownership tests rather than treating a basic widget/build pass as equivalent.
